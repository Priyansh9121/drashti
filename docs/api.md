# Drashti's local API (v1)

Drashti answers on the mandir's local network, once the operator turns the network on (**Phones** in the header, Pro Mode). The phone remote, the stage display and the announcements page use this API; so can a script, or Bitfocus Companion's generic HTTP actions on a Stream Deck. It is loosely modelled on the network API of the presentation software Drashti replaces: actions are short paths such as `/trigger/next` and `/clear/slide`, but every request must carry a paired device's token.

Everything here is **local only**: requests are refused from addresses outside the private ranges, from a Host header that is not this computer's own address or name, and (from a browser) from pages that are not Drashti's own. See README, "The local network", for the security model.

**Not here: the node link.** Output nodes (Session 13: other computers running Drashti as a Node) talk to Main on a port of their own (8741) over TLS with Main's own certificate, which each node pins when it pairs. That link is for Drashti alone and is not part of this API: a script or Companion cannot use it, and it refuses browsers. See README, "Output nodes".

## Basics

- **Address:** `http://<computer>:8740` (the port is set in the Phones panel). Examples below use

  ```sh
  DRASHTI=http://192.168.1.20:8740
  TOKEN=…   # a paired Remote device's token (see "A token for a script")
  ```

- **Versions:** everything is under `/api/v1`. Within v1, fields and requests may be added, never changed or taken away; a change that breaks would come as `/api/v2`.
- **Tokens:** every request except pairing needs `Authorization: Bearer <token>`. There are no cookies, and a token is never put in a URL. The one address that carries something else is a media file's original for a `<video>` or an `<audio>`, which cannot send the header (Session 54): a link the device asks for with its token, signed for that device and that file alone, which stops working after 6 hours, when Drashti starts again, or at once when the device is removed.
- **Kinds of device:** a **Remote** may run the show as the operator window does (everything below but `GET /api/v1/stage` and the announcements): it reads the library and puts up and takes off what is in it by id, and since Session 54 views the playlists shared with phones and tablets and, while **Phones and tablets may add files** is on, adds a file of its own, imported as a dropped file is ("Files" below). A **Stage** device only reads the state, the stage screen's settings and (Session 51) the pictures its audience picture box draws (since Session 54 at the width it draws them). An **Announcements** device only sends announcements and reads what became of its own. Anything else a device asks is refused (`403`). Beyond a Remote's own files, no device can change the library, the screens (their setup, or Main's Audience and Stage switches), video inputs, another app's window on the screens, the picture-in-picture box's setup, the sound, the stream, backups, the Access List, the Announcements queue or any settings: those stay in Drashti's own window.
- **Simple Mode** refuses over the network what it refuses in the operator window (`403`, saying so): switching the Look and, since Session 54, putting a zoom on the screens or Back to Whole, and moving or pausing what plays: the time bar's move, Back 15 s, Forward 15 s and Last 10 s, and the time bar's Pause, except an audio playlist's track's, which is Music's own Pause (a single sound's is refused too). Play always works, so nothing stays paused, and a jump to a marker is not refused. Reading, the rest of running the show and a phone's files (while adding is on) stay allowed in both modes.
- **Access** (Session 54, access by Gmail: `docs/access-setup.md`): Drashti works only on a computer that is let in. While it is not (at its lock screen, before it is let in, or once it has stopped: its access removed, its request rejected, this computer unknown to the list, or 2 minutes with no answer from it), every request is refused, pairing and files too (a preview, a picture, an original or its link, a file a phone adds): `503`, "Drashti has stopped: its access was removed or could not be checked. Nothing works until it is let in again." The feed too: a new one is refused as it opens (`503`), and one open as Drashti stops is closed with `{"type":"bye","reason":"stopped"}`. What is still being sent is cut off at once (an original a phone plays), and a file a phone is adding ends `failed`. The pages themselves still load, and say plainly that Drashti has stopped; a device stays paired, and works again once Drashti is let in.
- **Answers** are JSON: `{"ok": true, …}`, or `{"ok": false, "message": "…"}` with an HTTP status (an action the show refuses says `error` too, a short code such as `no-picture`):

  | Status   | Meaning                                                                                                                                                                                  |
  | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
  | 400      | The request is not right (a missing field, a slide that does not exist).                                                                                                                 |
  | 401      | No token, or one Drashti does not know (the device was removed): "This device is not paired with Drashti. Pair it again from Phones and tablets in Drashti."                             |
  | 403      | This kind of device may not do this, Simple Mode refuses it, adding files is off (Session 54), or the request came from outside the local network or another web page.                   |
  | 404      | No such request, playlist, presentation, media item, prop or lower third, or a file from a phone that Drashti no longer has.                                                             |
  | 405      | That request takes another method (actions are `POST`).                                                                                                                                  |
  | 409      | The show cannot do it now (nothing is live, nothing to put back, no logo chosen, nothing playing there, the picture zoomed no longer up), or a file's piece is not where Drashti has it. |
  | 411      | A file's piece without its length (Session 54).                                                                                                                                          |
  | 413, 415 | The body is too large (16 KB at most; a file a phone adds, 2 GB, and a piece of it, 8 MB), or is not JSON.                                                                               |
  | 421      | The Host header is not this computer's address.                                                                                                                                          |
  | 429      | Too many requests (about 20 a second per device), too many wrong pairing codes, or too many announcements or files from this device waiting.                                             |
  | 503      | Drashti is busy (a picture not made yet); try again. And every request while Drashti is not let in (Session 54, above).                                                                  |
  | 507      | Not enough free space on Drashti's computer for a file a phone adds (Session 54).                                                                                                        |

- **Actions** answer `{"ok": true, "changed": true, "rev": 42}`: `rev` is the engine state's revision after the action, which the state feed reaches too. Actions are `POST`, so a link or a browser's prefetch can never set one off. A body, when there is one, is JSON (`Content-Type: application/json`).

## A token for a script

Pair a **Remote** device in Drashti (Phones, then Pair a Remote device) and exchange the six-digit code (it works once, for two minutes) with `POST /api/v1/pair`, the one request that needs no token (five wrong codes a minute from one address, and every try is refused for the rest of the minute; after ten wrong tries in all the code stops working):

```sh
curl -s -X POST "$DRASHTI/api/v1/pair" -H 'Content-Type: application/json' -d '{"code":"123456"}'
# {"ok":true,"token":"…","device":{"name":"Remote 1","kind":"remote"}}
```

The token is shown this once; Drashti keeps only its hash. Keep it like a password. To take it away, remove the device in the Phones panel: it stops working at once.

## Reading

```sh
curl -s "$DRASHTI/api/v1/me" -H "Authorization: Bearer $TOKEN"
# {"ok":true,"device":{"name":"Remote 1","kind":"remote"}}

curl -s "$DRASHTI/api/v1/status" -H "Authorization: Bearer $TOKEN"
```

`GET /api/v1/status` (Remote, Stage) says where the show is, in short:

```json
{
  "ok": true,
  "status": {
    "live": {
      "presentationId": "…",
      "slideIndex": 2,
      "slideCount": 5,
      "playlist": { "playlistId": "…", "itemId": "…" },
      "onScreen": true
    },
    "blackout": false,
    "logo": false,
    "canPutBack": false,
    "next": { "kind": "slide", "presentationId": "…", "slideIndex": 3 },
    "messages": [{ "id": "message:…", "text": "Car 12 please move" }],
    "ticker": [{ "id": "…", "text": "Placeholder: prasad in the hall after arti" }],
    "timers": [{ "id": "…", "name": "Sabha starts in", "kind": "countdown", "running": true }],
    "stageMessage": false,
    "repeating": { "playlistId": "…", "name": "Lobby pictures" }
  }
}
```

`next` is what Next puts up: the next slide (`{"kind": "slide", "presentationId", "slideIndex"}`), the next playlist item when it is a picture, video or sound (`{"kind": "media", "itemId", "label"}`) or, since Session 51, a video input (`{"kind": "input", "itemId", "label"}`), or `null` when nothing comes next.

`repeating` is a Repeat Slides playlist going round (Session 26d), or `null`. While it goes round, `live.presentationId` is `repeat:` and the playlist's id: its steps are its pictures and its presentations' slides, in order.

**Pictures at a width** (Session 54): `width` is taken up to the next of 320, 640, 1280, 1920, 2560, 3840 and 7680. A JPEG, PNG, GIF or WebP no wider than that step is the file itself; anything else is made once by the bundled FFmpeg (a JPEG, or a PNG when it may be see-through) and kept, the least used going first when they come to 400 MB. A step being made for another request is waited for. When one cannot be made now (too many waiting, less than 2 GB free on Drashti's disk, a file FFmpeg cannot read), the answer is 503: keep the picture had so far, and ask again in a moment; a step that could not be made is not tried again for 5 minutes (503 meanwhile). Answers carry an `ETag`, so asking again for one already had costs nothing.

## Running the show (Remote)

```sh
curl -s -X POST "$DRASHTI/api/v1/trigger/next" -H "Authorization: Bearer $TOKEN"
curl -s -X POST "$DRASHTI/api/v1/trigger/back" -H "Authorization: Bearer $TOKEN"
curl -s -X POST "$DRASHTI/api/v1/blackout"     -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' -d '{"on":true}'
curl -s -X POST "$DRASHTI/api/v1/clear/all"    -H "Authorization: Bearer $TOKEN"
```

Since Session 54 the phone remote mirrors the operator window, laid out for the phone: besides Next and Back, the slides and the clears (named with their keys, `GET /api/v1/keys`), it puts up and takes off the props, the library's pictures, videos and sounds, the lower thirds, a timer alone on the screens, the stage message and the idle rotation, starts Repeat Slides going round, plays and pauses the audio playlists, and skips, moves, pauses and plays what plays. Each goes up or comes off as the operator window does it, and nothing here changes the library: a prop, a lower third or a media item is put up by its id, as Drashti reads it from the library, never sent whole.

## Files: shared playlists and adding from a phone (Remote)

Session 54. **Shared from Drashti:** a playlist the operator shares with phones and tablets (right-click it in Drashti, **Share with Phones and Tablets**; a folder playlist too) is listed here for Remote devices, to view and play on the device itself: its pictures and videos as any are (`GET /api/v1/media/{id}/picture` and `/original` above), and its sounds, whose originals are sent only while a shared playlist has them. It is read-only: nothing here changes it, and nothing here puts it on the screens (running the show goes through the playlist requests above, as before). Never for a Stage or Announcements device.

**Add from this Phone:** while **Phones and tablets may add files** is on in Drashti's Phones and tablets panel (off until someone turns it on, in Pro Mode; Simple Mode does not stop what comes while it is on), a Remote device may send a picture, video, sound, PDF, PowerPoint (`.pptx`; an older `.ppt` ends `failed`, its `message` saying to save it as `.pptx`) or Keynote file, up to 2 GB, whole and never shrunk. Drashti names the file on its computer itself (never by the name sent), keeps it in a folder of its media folder until it is imported, checks it by what is inside it (not by its name), and imports it as a file dropped on Drashti is: into the playlist **Added from Phones** (made when the first file comes) and Media (a deck into the library), named as the phone named it and marked with the device's name. It never goes live by itself. Drashti keeps 2 GB free on its disk, with the file and the import's copy of it in place. While the stream is on air or recording, the pieces are taken at about 2 MB a second, so the stream keeps its network; a PDF, PowerPoint or Keynote file, which its import converts, waits to be imported until the stream ends (its `message` says so meanwhile), and what Drashti cannot play is converted by itself afterwards, never on air.

## The state feed (WebSocket)

`ws://<computer>:8740/api/v1/feed` (Remote and Stage devices). The first message must say who the device is, within five seconds:

```js
const ws = new WebSocket('ws://192.168.1.20:8740/api/v1/feed');
ws.onopen = () => ws.send(JSON.stringify({ type: 'hello', token }));
ws.onmessage = (e) => {
  const m = JSON.parse(e.data);
  // {type:'welcome', device}, then {type:'engine', message: {kind:'snapshot', rev, state, …}},
  // then each change as {type:'engine', message: {kind:'patch', baseRev, rev, ops}}.
};
```

| From Drashti                                                                                 | Means                                                                                                                                                                                                                                                                                                                                                                   |
| -------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `{"type":"welcome","device":{"name","kind"}}`                                                | The token is good.                                                                                                                                                                                                                                                                                                                                                      |
| `{"type":"engine","message":{"kind":"snapshot","version","rev","state","sentAt","session"}}` | The whole state. `session` (since Session 53) is the run of the engine it is from: a new run (Drashti started again) counts its revisions from 0 again, so a copy takes a snapshot from another run whatever its `rev`.                                                                                                                                                 |
| `{"type":"engine","message":{"kind":"patch","version","baseRev","rev","ops","sentAt"}}`      | A change: apply `ops` (each replaces the value at `path`) to the state at `baseRev`.                                                                                                                                                                                                                                                                                    |
| `{"type":"clock","t0","server"}`                                                             | The answer to a clock message: the engine's time (ms since 1970) when it answered.                                                                                                                                                                                                                                                                                      |
| `{"type":"changed","what"}`                                                                  | A list changed: read it again. `what` is `playlists` (what is shared with phones too), `presentations` (the library, its media too), `messages`, `props`, `shastra`, `looks`, `screens`, and since Session 54 `lowerThirds`, `music` (the audio playlists), `keys` (the single-letter keys turned off or on) and `files` (above). A Stage device hears `screens` alone. |
| `{"type":"bye","reason"}`                                                                    | The connection is ending: `revoked` (the device was removed), `unauthorized`, `network-off`, `too-slow`, `not-allowed` (an Announcements device, which has no feed), or `stopped` (Session 54: Drashti stopped, or is not let in; the device stays paired).                                                                                                             |

| To Drashti                                 | Means                                                                                                                            |
| ------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------- |
| `{"type":"hello","token"}`                 | First, always.                                                                                                                   |
| `{"type":"clock","t0":<this device's ms>}` | Clock sync: of a few round trips, the shortest says how far this device's clock is from the engine's (`server - (t0 + t1) / 2`). |
| `{"type":"resync"}`                        | A revision went missing (`baseRev` is not the one held): send the whole state again.                                             |

A `version` the client does not know (`ENGINE_STATE_VERSION` in `src/shared/engine/state.ts`, 14 since Session 54: only additions to 13, below; 13 since Session 52: only additions to 12, and Session 53's below, which stayed 13 because no published release had read 13 yet; 12 since Session 48: a background of kind `window`, and Session 50's three additions and Session 51's below, which stayed 12 because no published release had read 12 yet; 11 since Session 44: the lower third's layer; 10 since Sessions 31–36: a slide's `darken`) means the state's shape changed: such a client should stop and say so. Output nodes (Session 13) follow the same engine messages over their own link.

A background of kind `window` (Session 48) is another app's window live on Main's own screens (`layers.background`: `sourceId`, `name`, `startedAt`). It is there to be named ("A window: Zoom Meeting"), never drawn: it is only on Main's computer. `POST /api/v1/clear/background` takes it off as any background; nothing on the network can put one up.

**Session 50** added three parts to the state, within version 12:

- **A background of kind `input`**: a video input live on Main's own screens, a camera or capture input on that computer (the video mixer's program through its USB output, say) that the operator named in Drashti (`layers.background`: `inputId`, `name`, `device` as the computer names it, `fit` (`fit` or `fill`), `startedAt`, and `fade`: `at` and `durationMs`, the second it dissolves in over). Like a window, it is there to be named ("Video input: Input 1"), never drawn: `POST /api/v1/clear/background` takes it off as any background.
- **A timer shown alone** (the Timers panel's **Show on the screens**): `layers.slide.timer` (`timerId`, `name`) says the slide in the slide's place is Drashti's Timer only layout made for that timer. Its `presentationId` is `timer:` and the timer's id, which no presentation in the library has; `live` stays where the show was, so Next goes on from there. `POST /api/v1/clear/slide` takes it off.
- **The picture-in-picture box**: `layers.pip`, or null. `source` is what it holds: `{"kind":"slides"}` (the slide, made small, while the main picture shows the background), `{"kind":"media","mediaId","media"}` (`media`: `image` or `video`), `{"kind":"input","inputId","name","device"}` or `{"kind":"window","sourceId","name"}`. `place` is where it sits and how it looks: `corner` (`top-left`, `top-right`, `bottom-left` or `bottom-right`, or null once dragged elsewhere), `x` and `y` (its top left, as fractions of the screen's width and height), `size` (`small`, `medium` or `large`: a quarter, a third or two fifths of the screen's width, always 16:9), `border`, `rounded` and `motion` (`fade`, `scale` or `slide`). `swapped` is true when its picture and the main picture changed places, `shownAt` is when it came on, and `changed` (when there is one) is the last Swap or move: its `at`, and the `place` and `swapped` from before it; `clips` (since Session 53, below) is its video's start and end points. `pipOff` beside `layers` is the box just taken off and when (`layer`, `at`), so every screen plays its going out from the same moment: null once a box is up again, and after Clear all and Put it back. `POST /api/v1/clear/pip` takes the box off, as Clear all does too.

A phone or a script may clear a video input and take the box off, and since Session 51 put one up only through a playlist or a slide (an item, or a slide's background), never from Media: a playlist's video input item started as any item (`POST /api/v1/trigger/item`), or a slide whose background is one put up (`POST /api/v1/trigger/slide`, or Next onto it). It never chooses a video input itself, or sets up, swaps or moves a box: those are the operator's, in Drashti's own window.

**Audience and Stage** (Session 50): `GET /api/v1/hall` answers with `switches`, whether Main's own audience screens (key and fill too) and stage screens are on: `{"audience": true, "stage": false}`. ## Companion (Stream Deck)

Bitfocus Companion's **Generic HTTP** connection drives Drashti with a Remote device's token:

1. Pair a Remote device for Companion (above) and keep its token.
2. Add a Generic HTTP connection. For each button, a **POST** action with the URL `http://192.168.1.20:8740/api/v1/trigger/next` (and so on, from the table above), the header `{"Authorization": "Bearer <token>"}`, and, where the request takes one, a JSON body such as `{"on": true}` with `Content-Type: application/json`.

## Events out (webhooks)

The other way round (Session 28): Drashti **sends** a signed `POST` to each address added under **File › Events Out…** (Pro Mode), for the kinds ticked there. Nothing is on until then. An address must be on this computer or the local network, unless it is the one `https` address on the internet the dialog allows. A receiver needs nothing from the API above: no token, no pairing.

**The body** is JSON:

```json
{
  "type": "slide.changed",
  "timestamp": "2026-10-16T19:30:05.123Z",
  "data": {
    "presentationId": "…",
    "slideIndex": 2,
    "slideCount": 5,
    "playlistId": "…",
    "itemId": "…",
    "repeat": false
  }
}
```

| `type`                                                   | `data`                                                                                                                                                                                                                             |
| -------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `slide.changed`                                          | `presentationId`, `slideIndex`, `slideCount`, `playlistId`, `itemId` (null when not from a playlist), `repeat` (true when a Repeat Slides playlist moved on by itself). A slide taken off: `presentationId` and `slideIndex` null. |
| `item.changed`                                           | `playlistId`, `itemId`.                                                                                                                                                                                                            |
| `blackout.changed`, `logo.changed`                       | `on`.                                                                                                                                                                                                                              |
| `stream.started`, `stream.reconnecting`                  | `places`: how many platforms it goes to.                                                                                                                                                                                           |
| `stream.ended`, `recording.started`, `recording.stopped` | Nothing.                                                                                                                                                                                                                           |
| `announcement.waiting`                                   | `announcementId`.                                                                                                                                                                                                                  |
| `screen.stopped`, `screen.showing`                       | `screenId`: a hall screen stopped, or came back.                                                                                                                                                                                   |
| `backup.finished`                                        | `outcome`: `done`, `skipped` or `failed`.                                                                                                                                                                                          |
| `drashti.test`                                           | Nothing: **Send a test**.                                                                                                                                                                                                          |

**Words** come only where **Include the words** is ticked for that kind at that address: `text` for `slide.changed` (the slide's lines, one to a line, 200 characters at most) and `announcement.waiting`, `name` for `screen.stopped` and `screen.showing`. Nothing else ever carries words, and keys, tokens, pairing codes, addresses and file paths never go.

**The headers:**

| Header                    | Holds                                                                                                                                                                                                    |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `webhook-id`              | The event's id (`msg_…`): the same on every try, so a receiver that sees it twice can drop the second.                                                                                                   |
| `webhook-timestamp`       | When this try was sent, in seconds since 1970.                                                                                                                                                           |
| `webhook-signature`       | `v1,` and the base64 HMAC-SHA256 of `id.timestamp.body`, keyed by the secret's bytes ([Standard Webhooks](https://www.standardwebhooks.com)). For a day after **New secret**, two, separated by a space. |
| `X-Drashti-Signature-256` | `sha256=` and the hex HMAC-SHA256 of the body, keyed by the whole secret as shown (`whsec_…`), as GitHub signs its webhooks: for a receiver that can only make a plain HMAC.                             |
| `X-Drashti-Event`         | The `type`, again.                                                                                                                                                                                       |

**Checking one**, in Node (a Standard Webhooks library does the first for you):

```js
import { createHmac, timingSafeEqual } from 'node:crypto';

const same = (a, b) => a.length === b.length && timingSafeEqual(Buffer.from(a), Buffer.from(b));

/** `body` exactly as it arrived, before any JSON parsing. */
function fromDrashti(secret, headers, body) {
  const id = headers['webhook-id'];
  const ts = headers['webhook-timestamp'];
  if (Math.abs(Date.now() / 1000 - Number(ts)) > 300) return false; // more than 5 minutes off
  const key = Buffer.from(secret.replace(/^whsec_/, ''), 'base64');
  const want = `v1,${createHmac('sha256', key).update(`${id}.${ts}.${body}`).digest('base64')}`;
  return headers['webhook-signature'].split(' ').some((s) => same(s, want));
}

/** Or the plain one. */
const githubStyle = (secret, headers, body) =>
  same(
    headers['x-drashti-signature-256'],
    `sha256=${createHmac('sha256', secret).update(body).digest('hex')}`,
  );
```

In n8n, the **Crypto** node's HMAC (SHA256, hex, the secret as shown) of the body as it arrived, with `sha256=` before it, should equal `X-Drashti-Signature-256`.

**Answering.** Answer `2xx` quickly (within 15 seconds; the body is not read). Anything else is tried again: at once, then after 5 s, 30 s, 2 min, 10 min and 30 min, and then the event is given up (the dialog counts those). Events to one address go one at a time, in order; slide changes within 250 ms of each other go as the last one. A `410` turns the address off until it is turned on again in the dialog; a `404`, a redirect (never followed) or another `4xx` means the address is set up wrongly, and is tried only twice more. Events waiting when Drashti quits are not sent later.
