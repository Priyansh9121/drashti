# Setup day: the checklist

This is the list for the day Drashti is set up on the mandir's two computers: for the admin doing the setup, with the operators there for the parts marked **(operators)**. Tick each line as it is done, and fill in the "Write down" table at the end. The steps say what to do; `docs/admin-guide.md` says how, and `docs/parallel-run.md` has the first evenings beside the old presentation program.

The old presentation program stays installed and untouched all day. Drashti only reads its files.

---

## Before the day

- [ ] **The audit**, on both computers, if it has not been run yet: `tools/audit/README.md`. Run each script with `--collect` (Mac) or `-Collect` (Windows) onto a USB drive, and keep that drive with you: its copies are raw and can hold licence details and personal data.
- [ ] **The setup checklist** (`tools/audit/SETUP-CHECKLIST.md`), printed and filled in by the operators: the screen map, the features each sabha uses, the keys they rely on, the sound, streaming, Gujarati and Hindi text, and how they switch back.
- [ ] **The OS versions** from the audit reports: the Mac needs macOS 13 (Ventura) or later, the PC 64-bit Windows 10 or 11. If either is older, stop and decide what to do first; do not update a show computer's OS on the day.
- [ ] **Which computer is Main**, and whether the other is a node or a Main of its own (admin guide, section 1).
- [ ] **The network**: a cable between the computers if possible, and Main's address reserved in the router by whoever looks after the mandir's network (admin guide, section 8).
- [ ] **The internet**: from 1.0.0-alpha.13 Drashti opens only once it has checked its access over the internet, and checks again every 15 seconds while it is open. With no answer, a bar at the top of its window counts down, and after 2 minutes everything stops (the screens, the stream, the node and the phones) until Drashti is quit and started again. So each computer that is a Main needs a network cable to the mandir's router, which has the internet; and a phone with its hotspot set up (and its charger) is the spare (admin guide, section 3).
- [ ] **The access list** in the approver Gmail, set up by its owner (`docs/access-setup.md`). On the day, whoever holds the approver Gmail must be able to open its emails (a phone is enough), as each request for access comes there; and the Gmail chosen for each mandir computer is one whose emails someone can open there too (one Gmail per computer: a mandir computer under the Gmail the owner chooses for it, and everyone at it works under that Gmail; an operator's own computer under the operator's own Gmail).
- [ ] **The installers**: the same Drashti version for both computers, on a USB drive (the setup kit holds that version only).
- [ ] **A private or unlisted YouTube stream** ready in YouTube Studio for the stream test (never the mandir's public one).
- [ ] **Bring**: two USB drives (one stays plugged in for backups), the key card printed from this version (end of `docs/parallel-run.md`; throw away any older card, as **F5** to **F8** and the logo's key have changed), a notebook, the operators' presentation clicker and any MIDI controller.

## 1. Install (both computers)

- [ ] Install Drashti from its download link (`docs/parallel-run.md`, section 2: the Apple-silicon or the Intel Mac's, or the Windows PC's).
- [ ] **On the Mac, the first time**: open the `.dmg`. Its window shows the two steps, with an arrow from Drashti to Applications: drag **Drashti** to **Applications**, then open it from Applications. If the Mac says Drashti can't be opened, press **Done**, then in **System Settings**, **Privacy & Security**, press **Open Anyway** beside the message about Drashti, confirm with the password or Touch ID, and press **Open Anyway** once more if macOS asks again. **Open Anyway** only shows there after that first try to open Drashti. Once on each Mac.
- [ ] **For whoever looks after Drashti**, instead of **Open Anyway**: once Drashti is in Applications, run `xattr -dr com.apple.quarantine /Applications/Drashti.app` in **Terminal**, and Drashti opens without the question.
- [ ] **On the Windows PC, the first time**: open the installer. If Windows says "Windows protected your PC", press **More info**, then **Run anyway**.
- [ ] **On an Intel Mac**, if the mandir has one (the old program's Mac may be one: **About This Mac** shows **Processor**: Intel): install the Intel Mac's file, check Drashti starts, and do the whole rehearsal (section 8) on it too. It has never yet run on a real Intel Mac.
- [ ] On the first start, choose **Main** on the first computer, and **Node** on the second if it will be one. A node needs no Gmail to run, but the performance check (section 8) runs only on a computer that is let in: for the node's, choose **Main** on it first, let it in as in the next line, then make it the node (**File**, **Use This Computer as a Node…**; on Windows press **Alt** for the menu).
- [ ] **(operators)** **Let each Main in** (admin guide, section 3; a node needs no Gmail of its own: it runs while its Main is let in), with its network cable in. **One Gmail per computer:** each mandir computer is let in once, under the Gmail the owner chooses for it, and everyone who works at it works under that Gmail. Drashti opens on its lock screen, **Let this computer in**. Under **Request Access**, that Gmail (and a name), then **Request Access**: it says the person who approves access has been emailed. The approver Gmail gets "Drashti: … asks for access", with an **Approve** and a **Reject** link: open **Approve**, and press **Approve** on the page it opens (the link works once, for 7 days). The lock screen then says **Approved** (it asks every 30 seconds, or press **Check Again**), and that Gmail gets "Your Drashti token": under **I Have a Token**, the same Gmail and that token, then **Let This Computer In**. Drashti opens, and from then on opens on this computer until its access is revoked. A token works once, on one computer, and runs out after 3 days unused: for a second Main with the same Gmail, see section 6. Write down whose Gmail let each computer in, never the token.
- [ ] Drashti shows its own logo, not a blue atom: in the Dock and Cmd+Tab on a Mac (on macOS 26 too, if a Mac runs it), in the taskbar, Alt+Tab and the Start menu on Windows. If a Mac still shows an older picture, restart it.
- [ ] Write down the version on each, from the right of the status bar along the bottom of the window (a node's is in Main's screens dashboard, once it is paired). They must be the same.
- [ ] **Check for Updates against the real release** (until now only tried against a test server), on Main (and the other computer if it is a Main too): **Help**, **Check for Updates…**, then **Check now**, with the internet on (on Windows press **Alt** for the menu). It names this version, 1.0.0-alpha.13, and says **It is the newest.**
- [ ] **On a computer that had an earlier Drashti** (from the parallel-run evenings, or a laptop it was tried on): after this version's first start, the two placeholder presentations, **Language test slides** and **Sample kirtan (placeholder)**, are gone from the library. One that was changed, or used in a playlist, a template or an arti schedule, stays, and the log says why (**Help**, **Save Diagnostics…**). Then make a throwaway presentation (**New…**, a line of placeholder words), open it in the middle, press **⋯** (Presentation actions) beside **Edit slides**, then **Delete…**: Drashti asks first, the middle then says **Nothing chosen yet**, and **Undo** brings the presentation back.

## 2. Bring in the library (Main)

- [ ] **(operators)** **Start and end points that come with the import** (never yet tried with the old program's own files), before the next line: one of the mandir's videos that has start and end points there, dragged alone from its folder into a throwaway playlist (**+ New**), and one click on it: it plays from its very start, as Drashti has no points for it yet. Leave it up while the next line's import comes in. Once that is in, the time bar under **Next** and **Back** shows the video's start and end points, and it plays between them at once, never put up again. Then delete the throwaway playlist.
- [ ] Press **Library** and drag the old program's folders (its `.pro6` and `.pro` files) onto its presentation list (`docs/parallel-run.md`, section 3), and any other folders the audit named.
- [ ] Read the report and **write down its numbers**: presentations, playlists, media, problems.
- [ ] **Media that could not be found** (the report's notice "… media files could not be found"): **Find missing media…**, and pick each folder the files are in (or **Find…** beside one file).
- [ ] **Media Drashti cannot play**: its videos and sounds convert by themselves, one at a time, a moment after the import. Each says **Converting…**, and cannot go live, until its copy is made, and the report says what was converted. HEVC video (as phones record) converts the same way on a computer that cannot play it, such as a Windows PC without Microsoft's HEVC extension; where it can, it plays as it is. Once, quit Drashti while one is still converting, and start it again: it says **Converting…** again, and those left start by themselves about 10 seconds after the window opens (never while the stream is on air or recording). Let them finish. For what is left (the notice "… media files Drashti cannot play", pictures such as HEIC among them; and in **Media**, any HEVC video still offering **Convert**): **Convert all**, and let it finish in the background.
- [ ] **Legacy fonts** the report's notes name (under **Imported with notes**): install each font on **Main and on the node** (admin guide, section 11). Quit and start Drashti again, and look at a few of those slides.
- [ ] **Words from Word files**: two of the mandir's own `.docx` files of a kirtan's words (they stay on these computers), one typed in Unicode and one in a legacy font. Drag each onto the library: each becomes a presentation, a slide for each block of lines, with the right letters; the report's notes name the legacy font, and its slides look right once that font is installed.
- [ ] **PowerPoint, Keynote and PDF decks**: drag them in. Where PowerPoint or Keynote is on this computer and **File**, **Decks With Their Animations on This Computer** is ticked (on a Mac from the start; on the Windows PC only once its tries below have passed), a deck comes in with its animations, or as picture slides when they cannot be made; with it unticked, as picture slides, its videos as real videos. A PDF's pages become picture slides. The first time, macOS asks whether Drashti may control Keynote or Microsoft PowerPoint: **Allow**. If the report says there is no Keynote or PowerPoint here, or that one could not open a deck, save the deck as PDF and drag in the PDF.
- [ ] **Keynote and PowerPoint on this computer** (never tried on these machines before the setup). With a placeholder deck (a few slides of made-up words, one hidden slide, one with an animation, speaker notes on some), not one of the mandir's: drag it in, and check the report names the app it used and says the hidden slide is left out, and that the slides' notes are right. Then check that the app closed again (or, if it was already open with something of yours, that it was left as it was). **On the Windows PC with PowerPoint** this is the first time it has ever run: also check PowerPoint showed no window, and drag in a deck while PowerPoint is open with an unsaved presentation: the presentation must still be there, unsaved. Write down how long the deck took (the report says, or the log: **Help**, **Save Diagnostics…**).
- [ ] **On the Windows PC with PowerPoint, a deck with a macro**, made on the day by whoever looks after Drashti (the kit has none): a placeholder deck holding a macro that shows a message, saved in the old format, a PowerPoint 97–2003 `.ppt`. First write down PowerPoint's own macro setting (**File**, **Options**, **Trust Center**, **Trust Center Settings…**, **Macro Settings**). Drag the deck in: its slides come in (with their animations, or as pictures), the message never shows, and that setting is as it was.
- [ ] **A deck with its animations, on the Windows PC with PowerPoint**, if it is a Main (never yet tried: there PowerPoint makes the deck's movie with its own video export, so its decks come in as pictures until **File**, **Decks With Their Animations on This Computer** is ticked; press **Alt** for the menu). Tick it for these tries, with placeholder decks only. Whoever looks after Drashti makes a placeholder deck in PowerPoint (the kit has none): about 20 slides of made-up words, a different transition on several, bullets that come in one click at a time, a line that comes in by itself, a motion path, a click that starts a chain (**After Previous**), and a shape that spins until the slide ends. Drag it in. Write down how long it took, and the report's words on where its steps fell in the movie ("the furthest … s from its moment": each should be within 0.2 s); check that no PowerPoint window showed and Drashti stayed in front. Once the screens are set up (section 3), step through it with **Next** and **Back** on the hall's projector: each click as in PowerPoint's own slide show, and as sharp.
- [ ] **The same deck with a video and a sound, while the show runs**: add to it, on one slide, a short placeholder video trimmed in PowerPoint (**Trim Video**), set to **Loop until Stopped** at **Volume** **Low**, and a placeholder sound that starts **Automatically**, and save it under another name. Once the screens are set up (section 3), drag it in with a video background playing on the hall's screens, nothing on air (Drashti never makes a deck's animations while the stream is on air or recording), and PowerPoint already open on an unsaved placeholder presentation. Write down how long it took this time, and whether the screens stuttered meanwhile; afterwards that presentation is still open in PowerPoint, and unsaved. On that slide the video plays from its trimmed start to its trimmed end and round again, as quiet as in PowerPoint's own slide show, with its time bar under **Next** and **Back**, and the sound starts as the slide goes up.
- [ ] **A deck's music across slides**, on each computer with the deck's app: a placeholder deck of four slides with a placeholder sound on the first set to **Play Across Slides**, and a second copy set to **Stop playing** after 2 slides (on the Mac, also a placeholder Keynote deck with a placeholder **Soundtrack**, then the same with it **Off**). The sound plays on from the hall's speakers through the clicks and slides, with its time bar under LIVE; **Back** never starts it again; the second stops as its third slide goes up; Keynote's soundtrack plays through to the end, and never when it is **Off**.
- [ ] **If either deck came in as pictures** instead, write down the report's words exactly: its slides are then pictures, its videos and sounds still real media. Only then: in PowerPoint, **Slide Show**, **Set Up Slide Show**, **Browsed by an individual (window)**, and start the slide show; in Drashti, **Library**, **Media**, **Show a Window…**, choose PowerPoint's slide show window, and **Show on the screens**. Write down whether a coloured border shows round it on the hall's screens, and whether its picture keeps moving while Drashti's window covers PowerPoint's.
- [ ] **A deck that makes PowerPoint ask something**, still with the tick on: a placeholder deck PowerPoint asks about as it opens it, such as one saved with a **Password to modify** (in PowerPoint, **File**, **Save As**, **More options…**, **Tools**, **General Options…**). First write down PowerPoint's macro setting, as for the deck with a macro. Drag it in: Drashti gives up on it after a minute or two, the report saying it stopped as when PowerPoint asks something in a window nobody sees, and PowerPoint's macro setting is as it was afterwards (if the report says PowerPoint's settings could not be put back, quit PowerPoint and open it again). If PowerPoint asked nothing and the deck came in, write that down: that deck was no test of it.
- [ ] **Then, on the Windows PC**: if the tries above passed (each step within 0.2 s, no PowerPoint window, Drashti in front, the screens smooth, PowerPoint's own presentation and settings as they were), leave **Decks With Their Animations on This Computer** ticked. If not, untick it, so that its decks come in as pictures with their videos as real videos, and write down why.
- [ ] **On the Mac, Keynote's trims**: write down the versions of Keynote and PowerPoint (each app's own menu, **About Keynote**, **About Microsoft PowerPoint**). In Keynote, make a placeholder deck of a few slides of made-up words, with a short placeholder video trimmed in Keynote. Drag it in: its video plays whole, as the report says (Keynote does not tell Drashti a video's trims). Then in Keynote, **File**, **Export To**, **PowerPoint…**, and open that copy in PowerPoint, if it is installed: write down whether its video is trimmed there.
- [ ] **(operators)** **One of the mandir's own decks with animations, on each computer that is a Main** with PowerPoint or Keynote and **Decks With Their Animations on This Computer** ticked: the Mac, where it is on from the start, and the Windows PC only if it was left ticked above (the deck stays on these computers). Drag it in (for one already in the library as pictures, from the parallel-run evenings, Drashti asks first: **Replace** it, or **Keep both**) and, once the screens and a phone are set up (sections 3 and 5), step through it with **Next** and **Back** beside the deck's own slide show. Every click, transition, video and sound comes as the operators expect; the status along the top says which click is up ("click 1 of 2"); the stage screen shows the click that is up and the next one, and a phone each click's still. Write down how long it took, and anything different.
- [ ] **Import from a Link with a real Dropbox link** (never tried against Dropbox itself: the tests use a stand-in). With a Dropbox link to one of the mandir's own short videos, and one to a mandir folder holding a placeholder `.pptx`, a short MP4, a placeholder PDF and a few pictures, some of them in a folder inside it: **File**, **Import from a Link…**, **Dropbox**, paste, **Download**, into a test folder (admin guide, section 14). Write down: whether each link was looked at (its name and size shown), saved and imported; that the folder came as a playlist of its own, its inside folder under a header, and its PDF and pictures came in with **Add the PDFs and pictures**; and anything the window said. If Dropbox refused, write its exact words. Then the same on the other computer, if it is a Main too.
- [ ] **Import from a Link with one of the mandir's own YouTube videos** (never tried against YouTube itself: the tests use a fake yt-dlp). An admin, with a short video from the mandir's own channel: **File**, **Import from a Link…**, **YouTube**, paste its Share link, choose **MP4** at **1080p**, tick the box, **Download**, into a test folder; then the same video as **MP3** (admin guide, section 14). Once only on each computer that is a Main. Write down: whether the title and length showed, the qualities offered, how long each took, whether each was saved and imported and plays, and anything the window said (its exact words if it refused). Each time a download is in, the playlist it went into opens with the new item chosen, never live: write down whether the operators would mind that in the middle of a sabha.
- [ ] **A 4K video on the Windows PC** (nobody has measured one there): in the same window, set **Highest video quality** to **2160p (4K)**, and download one of the mandir's videos that YouTube offers at **2160p** (YouTube sends it as VP9 or AV1; if none is offered at 2160p, write that down). Then set **Highest video quality** back to **1080p**. Once the screens are set up (section 3), put it up as a background for a minute on the screens the PC drives: write down whether it plays smoothly on each.
- [ ] **The drop folder**, if the mandir will use one (admin guide, section 18): **File**, **Drop Folder…**, **Choose…** the folder (choosing it turns it on). Put a picture, a short video and a sound in it: a few seconds later each is in **Media** by itself, under **From the drop folder**, and a notice says how many came in. If it is a synced Dropbox or OneDrive folder, try it there: Drashti warns that a folder on this computer alone is safer, and still takes each file only once it has all arrived.
- [ ] **A smart playlist on a USB stick**, if the mandir will use one (admin guide, section 15): **+ New**, **Smart Playlist from a Folder…**, and a folder on the stick holding a few placeholder files. Put one more file in: it joins at the end by itself. Take one out: its item says **Not in the folder**, and still plays. Pull the stick out: the line under the playlist's name says the folder is not there, and nothing is lost; put it back, and it carries on.
- [ ] **(operators)** Open five kirtans they know well and compare with the old program: the words, the line breaks, the Gujarati and Hindi letters, the backgrounds.
- [ ] **Back up**: **File**, **Back Up Library…**, with the media, to the USB drive.
- [ ] **Scheduled backups**: **File**, **Scheduled Backups…**, onto the drive that stays plugged in (admin guide, section 5). Press **Back up now** once and check it finishes.

## 3. Screens and sound (Main, then the node)

- [ ] **Set Up Screens…** (in **View**): **Show each display's number on it**, then for each display what it shows (one click) and its languages, as the screen map in the checklist says, and **Done**. (With only the hall's display connected, **Show on** it under the top bar does the hall in one click.)
- [ ] **Keep these screens?** In **Set Up Screens…**, **The controls are on this display** marks the operator's display: check it is the right one. After **Done**, Drashti asks for 15 seconds: **Keep** (Enter) or **Go back** (Esc). Try **Go back** once: the screens are as they were, and **Set Up Screens…** shows the choices again to put right. Then press nothing once: after 15 seconds the screens go back by themselves, and a notice says so. In **Screens**, changing what a group **Shows** (or what a key and fill screen **Sends**) asks too. Once, while it asks, stop Drashti as a power cut would, with a forced quit (on a Mac **Option+Cmd+Esc**, **Drashti**, **Force Quit**; on Windows, in PowerShell, `Stop-Process -Name Drashti -Force`), and start it again: the screens are as they were before that change, and a notice says so. Last, **Done** and **Keep**.
- [ ] **Sound** (**Set Up Screens…**, then **More setup…**): the output to the mixer, and **Play a test tone**. **(operators)** Check the mixer hears it on the right channel.
- [ ] Canvas sizes and scaling for any screen that is not 1920 × 1080 (an LED wall).
- [ ] **(operators)** **Looks**: the everyday Look first in the list, then any others they need ("Gujarati only", "Lower thirds"). On the Windows PC, untick two of a Look's **Layers on these screens** quickly, one after the other, then tick both again, also while an import is running: each stays as it was left.
- [ ] **(operators)** **Stage layout**: with the performers, the boxes they want on the stage screen.
- [ ] **(operators)** **The hall's picture on a stage screen**, if the mandir wants it under the stage message, as the old program showed it: in their stage layout (**Edit stage layouts…** under the stage group in **Screens**), choose **The audience picture, live** in the list of boxes beside **Add**, then **Add**. It goes under the boxes already there, so the stage message draws over it. Place and size it, and **Save**. On the stage screen it matches the hall's screens: the slide, the background, black-out and the logo. With **Audience** off it keeps the picture and says **Audience off** in its bottom left corner, where a stage message along the top does not cover it (a box of the audience screens' state says "Audience screens off"). On a node with no hall screen of its own that is on, it shows Main's hall as the live Look has it. A tablet's stage display (section 5) shows it too, each picture or video in it as a small still (a video input or a window is black there, named in a small line in the box's bottom left corner). With no audience group in **Screens** at all, the box is black and says **No audience screens**, and so does a box of the audience screens' state.
- [ ] **(operators)** **The audience picture box at its smallest**: in the layout editor, drag a corner of **The audience picture, live** in as far as it goes: it stops at 320 × 180, as its **Width** and **Height** say. **Save**, and look at the stage screen from where the performers stand. Turn **Audience** off: **Audience off** can be read in the box; turn it on again. Then, for a moment, change what the hall's group **Shows** in **Screens** to **The stage view (performers)**: while Drashti asks whether to keep it, with no other group showing **The audience picture**, the box says **No audience screens**, as does a box of the audience screens' state if the layout has one (**The audience screens (black-out, logo)** in the list of boxes). Press **Go back**. Last, size the box as the performers want it, and **Save**.
- [ ] **(operators)** **A stage timer from a template, on the real stage screen**: in **Edit stage layouts…**, **New from a Template…**, **Countdown**, a **Length** of 2:00, then **Make the layout**. It makes the timer ("Stage countdown" in **Timers**), and the stage screens show the new layout at once, in the live Look. Choose the timer's box, turn on **Flash at 0:00**, and **Save**. Then **Start** beside it in the **Stage screen** panel, and watch from where the performers stand: the digits are white until 1:00 is left, then amber, then red at 0:00 and past it, where they flash for 10 seconds, dim a second and bright a second. Write down whether the flash is seen and is not too much, and whether the digits jump in size as 0:00 becomes -0:01. **Reset**. In **Looks**, choose another Look for a moment: its stage screens keep that Look's own layout, as the template's is chosen in the live Look only; write down whether the operators want it in every Look.
- [ ] **(operators)** **The other templates, on the real stage screen**: **Countdown to a time** shows the same time left on the stage screen and, once they are paired, on a node's stage screen (the last line of this section) and the tablet's stage display (section 5): each works out the time of day in its own time zone, so check each device is set to the mandir's. **Timer and clock over the audience**: with a bright picture up on the hall's screens, the timer and the clock, each on its see-through black, can be read from where the performers stand. On the Windows PC, if Windows has a Gujarati or Hindi keyboard added: in the layout editor, choose a box and press **Alt+Shift** and an arrow key: write down whether the box changes size by ten pixels, or Windows changes the keyboard instead. Last, choose the layout the performers want (in **Screens**, the stage group's **Stage layout**).
- [ ] **Masks** for any screen that is not a rectangle, or a projector that spills: draw each over the hall screen's live picture in the mask editor, so it fits what is really there.
- [ ] **Key and fill**, if the mandir's video switcher lays words over the camera: set the switcher's key to **pre-multiplied**, and check a lower third keys cleanly over a camera, with no white edge round its words, as it comes in, changes and goes out.
- [ ] **Audience and Stage** (Main): the two switches in the top bar beside **Screens**, or **Cmd+1** and **Cmd+2** (**Ctrl+1** and **Ctrl+2** on Windows), which **View** shows beside its **Audience** and **Stage**. With a slide up, turn **Audience** off (Drashti asks first: **Turn off**): the projector shows the computer's desktop, and the status bar says **Audience off**; turning its screen off and on again in **Screens** meanwhile asks nothing. Turn it on: the hall's picture comes back full-screen on the same display, asking nothing. Do it once from **View**, **Audience**, too. Then **Stage** off (**Turn off** again) and on: each of the three stage screens shows the desktop, then the stage view again on its own display. If key and fill is used, **Audience** turns its two feeds off and on too. Last, with an output put over the controls (Drashti asks first: **Cover the controls**, then **Keep**), **Cmd+1** asks on that output too, large in its middle and readable from the hall: **Esc** cancels; **Cmd+1** again and **Enter** turns Audience off, and the controls are back. Turn it on again, and **Cmd+Shift+U** (**Ctrl+Shift+U**) takes that output off the controls. The show, the stream and the node carry on throughout.
- [ ] **The video mixer as a video input** (Main): the ATEM's program, through its USB output into Main. **Library**, **Media**, **Add a Video Input…**. On the Mac, unless Drashti may use the camera already, it says why first: **Continue**, then **Allow** when macOS asks (if it was refused: **Open System Settings**, turn **Drashti** on under **Camera**, then **Look again**). On Windows, if Drashti says Windows' camera privacy setting is off: **Open Settings**, turn on **Camera access** and **Let desktop apps access your camera**, then **Look again**. The mixer shows by its name, with its small live picture: choose it, keep the name **Input 1**, and **Add to Media**. It is listed under **Video inputs** at the top of **Media**. Write down the name the mixer showed under. If the second computer is a Main of its own, or the library may go to another computer, name that computer's video input **Input 1** too: playlists and slides name the input, and where no input has that name they say so (**Not on this computer**). If it is renamed later (its **Change** in **Media**), this computer's playlists and slides take the new name with it: give the other computer's input the same new name, or there they say **Not on this computer**.
- [ ] **What a new name does** (Main): press **Change** at the end of **Input 1**'s row in **Media** (the pencil). Before a new name is typed, a muted line under **Name** and **Fit** says that this computer's playlist items and slides that use it take the new name, and that the other computer's input needs the same new name. Type a new name (**Input 2**): the dialog keeps its size and place, with **Cancel** and **Save** in sight on the operator's display. Then **Cancel**: it is still **Input 1**.
- [ ] **The node** (if there is one): **Pair a node** on Main, give the node's displays their groups, and tick **Get everything ready** in the screens dashboard. In the screens dashboard, the node says **Online** and its media all ready.

## 4. The show's own things (Main)

- [ ] **The logo**: in **Props**, the stamp button beside the mandir's logo prop.
- [ ] **(operators)** Props, message templates and timers they use, from the checklist's "Features used".
- [ ] **(operators)** Any MIDI pads (**More tools**, **MIDI controller…**, **Learn**).
