# Setup day: the checklist

Use this checklist with **1.0.0-alpha.17**. Live captions start off, are marked **Trial** and can slow the screens while on.

This is the list for the day Drashti is set up on the mandir's two computers: for the admin doing the setup, with the operators there for the parts marked **(operators)**. Tick each line as it is done, and fill in the "Write down" table at the end. The steps say what to do; `docs/admin-guide.md` says how, and `docs/parallel-run.md` has the first evenings beside the old presentation program.

The old presentation program stays installed and untouched all day. Drashti only reads its files.

---

## Before the day

- [ ] **The audit**, on both computers, if it has not been run yet: `tools/audit/README.md`. Run each script with `--collect` (Mac) or `-Collect` (Windows) onto a USB drive, and keep that drive with you: its copies are raw and can hold licence details and personal data.
- [ ] **The setup checklist** (`tools/audit/SETUP-CHECKLIST.md`), printed and filled in by the operators: the screen map, the features each sabha uses, the keys they rely on, the sound, streaming, Gujarati and Hindi text, and how they switch back.
- [ ] **The OS versions** from the audit reports: the Mac needs macOS 13 (Ventura) or later, the PC 64-bit Windows 10 or 11. If either is older, stop and decide what to do first; do not update a show computer's OS on the day.
- [ ] **Which computer is Main**, and whether the other is a node or a Main of its own (admin guide, section 1).
- [ ] **The network**: a cable between the computers if possible, and Main's address reserved in the router by whoever looks after the mandir's network (admin guide, section 8).
- [ ] **The internet**: Drashti checks its access over the internet as it starts, and again every 15 seconds while it is open. Within 15 days of an answer that let this computer in, it opens at once, with the internet or without it. With no answer, it keeps working, the stream and recording included; after about 2 minutes a line under the top bar counts down how long ("Can’t reach the access list: Drashti keeps working for 14 days 6 hours more."). After 15 days with no answer, everything stops (the screens, the stream, the node and the phones), and this computer must ask for access again. So each computer that is a Main needs a network cable to the mandir's router, which has the internet; and a phone with its hotspot set up (and its charger) is the spare (admin guide, section 3).
- [ ] **The access list** in the approver Gmail, set up by its owner (`docs/access-setup.md`), with this version's files put in before the day (section 11 there): until then, Drashti opens only with the internet. On the day, whoever holds the approver Gmail must be able to open its emails (a phone is enough), as each request for access comes there; and the Gmail chosen for each mandir computer is one whose emails someone can open there too (one Gmail per computer: a mandir computer under the Gmail the owner chooses for it, and everyone at it works under that Gmail; an operator's own computer under the operator's own Gmail).
- [ ] **Pro or Simple, for each Gmail**: the owner decides what each may use. Each mandir computer's Gmail is given **Pro** (**Pro Mode and Simple Mode**), or Simple (**Simple Mode only**) for a computer that runs a hall with one projector. Approve from the email's Approve page or from this version's **Access List** (**View**, **Access List…**, on the owner's computer), never from alpha.13's: it sends no mode, so the Gmail gets Simple. In the Sheet, never delete or rename the **Mode** column: every computer but the owner's would go to Simple Mode at its next check, until **Pro** is typed in again.
- [ ] **The daily check**, once, by the owner: first check the Sheet's time zone is the mandir's (**File** › **Settings** › **Time zone**: the check runs at about 3 in the morning there), then in the Sheet, **Drashti** › **Turn on the daily check…**. Google asks once for the one permission it needs ("Allow this application to run when you are not present"): allow it. From then on, once a day, the list ends the access of each computer that has not checked in for 15 days.
- [ ] **The installers**: the same Drashti version for both computers, on a USB drive (the setup kit holds that version only).
- [ ] **A private or unlisted YouTube stream** ready in YouTube Studio for the stream test (never the mandir's public one).
- [ ] **Bring**: two USB drives (one stays plugged in for backups), the key card printed from this version (**Keys at a glance**, at the end of `docs/parallel-run.md`; throw away any older card: **F4** and **F8** do nothing now, **F9** is **Oops**, **F12** puts the wallpaper up where it put the logo, and **L** has gone), the mandir's darshan pictures for the wallpapers (section 4), a notebook, the operators' presentation clicker and any MIDI controller.

## 1. Install (both computers)

- [ ] Install Drashti from its download link (`docs/parallel-run.md`, section 2: the Apple-silicon or the Intel Mac's, or the Windows PC's).
- [ ] **On the Mac, the first time**: open the `.dmg`. Its window shows the two steps, with an arrow from Drashti to Applications: drag **Drashti** to **Applications**, then open it from Applications. If the Mac says Drashti can't be opened, press **Done**, then in **System Settings**, **Privacy & Security**, press **Open Anyway** beside the message about Drashti, confirm with the password or Touch ID, and press **Open Anyway** once more if macOS asks again. **Open Anyway** only shows there after that first try to open Drashti. Once on each Mac.
- [ ] **For whoever looks after Drashti**, instead of **Open Anyway**: once Drashti is in Applications, run `xattr -dr com.apple.quarantine /Applications/Drashti.app` in **Terminal**, and Drashti opens without the question.
- [ ] **On the Windows PC, the first time**: open the installer. If Windows says "Windows protected your PC", press **More info**, then **Run anyway**.
- [ ] **On an Intel Mac**, if the mandir has one (the old program's Mac may be one: **About This Mac** shows **Processor**: Intel): install the Intel Mac's file, check Drashti starts, and do the whole rehearsal (section 8) on it too. It has never yet run on a real Intel Mac.
- [ ] On the first start, choose **Main** on the first computer, and **Node** on the second if it will be one. A node needs no Gmail to run, but the performance check (section 8) runs only on a computer that is let in: for the node's, choose **Main** on it first, let it in as in the next line, then make it the node (**File**, **Use This Computer as a Node…**; on Windows press **Alt** for the menu).
- [ ] **(operators)** **Let each Main in** (admin guide, section 3; a node needs no Gmail of its own: it runs while its Main is let in), with its network cable in. **One Gmail per computer:** each mandir computer is let in once, under the Gmail the owner chooses for it, and everyone who works at it works under that Gmail. Drashti opens on its lock screen, **Let this computer in**. Under **Request Access**, that Gmail (and a name), then **Request Access**: it says the person who approves access has been emailed. The approver Gmail gets "Drashti: … asks for access", with an **Approve** and a **Reject** link: open **Approve**. On the page it opens, leave **Unlimited, until you revoke it** chosen under **How long may they use Drashti?** (every mandir computer's Gmail is given Unlimited, so a date never cuts off a sabha); under **What may they use?**, choose **Pro Mode and Simple Mode** (**Simple Mode only** is chosen at first: keep it only for a computer that runs a hall with one projector); then press **Approve** (the link works once, for 7 days). The lock screen then says **Approved** (it asks every 30 seconds, or press **Check Again**), and that Gmail gets "Your Drashti token", which says what it may use: under **I Have a Token**, the same Gmail and that token, then **Let This Computer In**. Drashti opens in Pro Mode (in Simple Mode, with **Simple Mode only**), and from then on opens on this computer until its access is revoked: at once, with the internet or without it, within 15 days of its last check (no bar about when access ends: Unlimited has no end). A token works once, on one computer, and runs out after 3 days unused: for a second Main with the same Gmail, see section 6. Write down whose Gmail let each computer in, and Pro or Simple, never the token.
- [ ] Drashti shows its own icon, not a blue atom: in the Dock and Cmd+Tab on a Mac (on macOS 26 too, if a Mac runs it), in the taskbar, Alt+Tab and the Start menu on Windows. If a Mac still shows an older picture, restart it.
- [ ] Write down the version on each, from the right of the status bar along the bottom of the window (a node's is in Main's screens dashboard, once it is paired). They must be the same.
- [ ] **Check for Updates against the real release** (until now only tried against a test server), on Main (and the other computer if it is a Main too): **Help**, **Check for Updates…**, then **Check now**, with the internet on (on Windows press **Alt** for the menu). It names this version, 1.0.0-alpha.16, and says **It is the newest.**
- [ ] **On a computer that had an earlier Drashti** (from the parallel-run evenings, or a laptop it was tried on): after this version's first start, the two placeholder presentations, **Language test slides** and **Sample kirtan (placeholder)**, are gone from the library. One that was changed, or used in a playlist, a template or an arti schedule, stays, and the log says why (**Help**, **Save Diagnostics…**). Then make a throwaway presentation (**New…**, a line of placeholder words), close the open playlist (**×**) and choose the presentation in the library, so that it fills the middle, press **⋯** (Presentation actions) beside **Edit slides**, then **Delete…**: as it is in no playlist and not up, it goes at once, the middle then says **Nothing chosen yet**, and **Undo** brings the presentation back.
- [ ] **What this version took out**, on that computer: props, Looks, masks, themes, the logo and the idle rotation are gone from the window, the menus, the keys and the phones. The library keeps them, unseen, so nothing in it is lost. In **Screens**, each screen group's languages are as before (they moved there from its Look), and an idle rotation's pictures and quotes are now the wallpaper **Idle rotation** (section 4). A presentation's words are changed in **Edit slides…** (in its right-click menu, or **Edit slides** in the middle).

## 2. Bring in the library (Main)

- [ ] **(operators)** **Start and end points that come with the import** (never yet tried with the old program's own files), before the next line: one of the mandir's videos that has start and end points there, dragged alone from its folder into a throwaway playlist (**+ New**), and one click on it: it plays from its very start, as Drashti has no points for it yet. Leave it up while the next line's import comes in. Once that is in, the time bar under **Next** and **Back** shows the video's start and end points, and it plays between them at once, never put up again. Then delete the throwaway playlist.
- [ ] Press **Library** and drag the old program's folders (its `.pro6` and `.pro` files) onto its presentation list (`docs/parallel-run.md`, section 3), and any other folders the audit named.
- [ ] When it finishes, **write down what the status bar says** (presentations, media files, problems) and each notice in the bottom-right corner (since alpha.17 no report opens).
- [ ] **Media that could not be found** (a presentation's notice says its media could not be found): **Find…** on that notice, and pick the folder the files are in; **Find missing media…** in **Ready?** does the same for the open playlist.
- [ ] **Media Drashti cannot play**: its videos and sounds convert by themselves, one at a time, a moment after the import. Each says **Converting…**, and cannot go live, until its copy is made (**Media** shows each converting); nothing converts while anything is up or playing (music too) or the stream is on air or recording. Pictures a screen cannot show as they are (HEIC, TIFF, Photoshop and others) are converted the same way; a JPEG XL picture, an SVG drawing or a camera's raw picture is turned down, a notice saying why (save it as a JPEG or a PNG). HEVC video (as phones record) converts the same way on a computer that cannot play it, such as a Windows PC without Microsoft's HEVC extension; where it can, it plays as it is. Once, quit Drashti while one is still converting, and start it again: it says **Converting…** again, and those left start by themselves about 10 seconds after the window opens (never while anything is up or playing, or the stream is on air or recording). Let them finish. For what is left (in **Media**, anything still offering **Convert**, such as an HEVC video): **Convert all**, and let it finish in the background.
- [ ] **Legacy fonts** (such as Gopika, Terafont or Kruti Dev; since alpha.17 nothing names them at import, so look through the older slides for letters that look wrong): install each font on **Main and on the node** (admin guide, section 11). Quit and start Drashti again, and look at a few of those slides.
- [ ] **Words from Word files**: two of the mandir's own `.docx` files of a kirtan's words (they stay on these computers), one typed in Unicode and one in a legacy font. Drag each onto the library: each becomes a presentation, a slide for each block of lines, with the right letters; the legacy font's slides look right once that font is installed.
- [ ] **PowerPoint, Keynote and PDF decks**: drag them in. Where PowerPoint or Keynote is on this computer and **File**, **Decks With Their Animations on This Computer** is ticked (on a Mac from the start; on the Windows PC only once its tries below have passed), a deck comes in with its animations (its slides show at once, and a slide with animations says **Preparing** until its clicks are made), or as picture slides when they cannot be made; with it unticked, as picture slides, its videos as real videos. A PDF's pages can be shown at once, then prepared for editing in Edit slides… (section 8). The first time, macOS asks whether Drashti may control Keynote or Microsoft PowerPoint: **Allow**. With PowerPoint, macOS may also ask whether Drashti may access data from other apps ("“Drashti” would like to access data from other apps"): **Allow** that too, as Drashti hands PowerPoint the deck in PowerPoint's own folder. Since alpha.16 Drashti no longer reads that folder as it starts (but to tidy up after an import cut short), so the question should not come at each start: write it down if it does. If a notice says there is no Keynote or PowerPoint here, or that one could not open a deck, save the deck as PDF and drag in the PDF.
- [ ] **Keynote and PowerPoint on this computer** (never tried on these machines before the setup). With a placeholder deck (a few slides of made-up words, one hidden slide, one with an animation, speaker notes on some), not one of the mandir's: drag it in, and check that a notice says the hidden slide is left out, and that the slides' notes are right (the log, **Help**, **Save Diagnostics…**, says how it came in). Then check that the app closed again (or, if it was already open with something of yours, that it was left as it was). **On the Windows PC with PowerPoint** this is the first time it has ever run: also check PowerPoint showed no window, and drag in a deck while PowerPoint is open with an unsaved presentation: the presentation must still be there, unsaved. Write down how long the deck took (the log has it: **Help**, **Save Diagnostics…**).
- [ ] **On the Windows PC with PowerPoint, a deck with a macro**, made on the day by whoever looks after Drashti (the kit has none): a placeholder deck holding a macro that shows a message, saved in the old format, a PowerPoint 97–2003 `.ppt`. First write down PowerPoint's own macro setting (**File**, **Options**, **Trust Center**, **Trust Center Settings…**, **Macro Settings**). Drag the deck in: its slides come in (with their animations, or as pictures), the message never shows, and that setting is as it was.
- [ ] **A deck with its animations, on the Windows PC with PowerPoint**, if it is a Main (never yet tried: there PowerPoint makes the deck's movie with its own video export, so its decks come in as pictures until **File**, **Decks With Their Animations on This Computer** is ticked; press **Alt** for the menu). Tick it for these tries, with placeholder decks only. Whoever looks after Drashti makes a placeholder deck in PowerPoint (the kit has none): about 20 slides of made-up words, a different transition on several, bullets that come in one click at a time, a line that comes in by itself, a motion path, a click that starts a chain (**After Previous**), and a shape that spins until the slide ends. Drag it in. Write down how long it took, and any notice that a slide came in as its picture (a step more than 0.2 s from its moment in the movie); check that no PowerPoint window showed and Drashti stayed in front. Once the screens are set up (section 3), step through it with **Next** and **Back** on the hall's projector: each click as in PowerPoint's own slide show, and as sharp.
- [ ] **The same deck with a video and a sound, while the show runs**: add to it, on one slide, a short placeholder video trimmed in PowerPoint (**Trim Video**), set to **Loop until Stopped** at **Volume** **Low**, and a placeholder sound that starts **Automatically**, and save it under another name. Once the screens are set up (section 3), drag it in with a video background playing on the hall's screens, nothing on air (Drashti never makes a deck's animations while the stream is on air or recording), and PowerPoint already open on an unsaved placeholder presentation. Write down how long it took this time, and whether the screens stuttered meanwhile; afterwards that presentation is still open in PowerPoint, and unsaved. On that slide the video plays from its trimmed start to its trimmed end and round again, as quiet as in PowerPoint's own slide show, with its time bar under **Next** and **Back**, and the sound starts as the slide goes up.
- [ ] **A deck's music across slides**, on each computer with the deck's app: a placeholder deck of four slides with a placeholder sound on the first set to **Play Across Slides**, and a second copy set to **Stop playing** after 2 slides (on the Mac, also a placeholder Keynote deck with a placeholder **Soundtrack**, then the same with it **Off**). The sound plays on from the hall's speakers through the clicks and slides, with its time bar under LIVE; **Back** never starts it again; the second stops as its third slide goes up; Keynote's soundtrack plays through to the end, and never when it is **Off**.
- [ ] **If either deck came in as pictures** instead, write down its notice's words exactly: its slides are then pictures, its videos and sounds still real media. Only then: in PowerPoint, **Slide Show**, **Set Up Slide Show**, **Browsed by an individual (window)**, and start the slide show; in Drashti, **Library**, **Media**, **Show a Window…**, choose PowerPoint's slide show window, and **Show on the screens**. Write down whether a coloured border shows round it on the hall's screens, and whether its picture keeps moving while Drashti's window covers PowerPoint's.
- [ ] **A deck that makes PowerPoint ask something**, still with the tick on: a placeholder deck PowerPoint asks about as it opens it, such as one saved with a **Password to modify** (in PowerPoint, **File**, **Save As**, **More options…**, **Tools**, **General Options…**). First write down PowerPoint's macro setting, as for the deck with a macro. Drag it in: Drashti gives up on it after a minute or two, a notice saying it stopped as when PowerPoint asks something in a window nobody sees, and PowerPoint's macro setting is as it was afterwards (if the notice says PowerPoint's settings could not be put back, quit PowerPoint and open it again). If PowerPoint asked nothing and the deck came in, write that down: that deck was no test of it.
- [ ] **Then, on the Windows PC, the tick for good** (an admin, at the weekend): **File**, **Decks With Their Animations on This Computer** is off on Windows until the mandir PC has passed the tries above, its try-list. If they passed (each step within 0.2 s, no PowerPoint window, Drashti in front, the screens smooth, PowerPoint's own presentation and settings as they were), leave it ticked: from then on that PC's decks come in with their animations, and nothing more is needed. If not, untick it, so that its decks come in as pictures with their videos as real videos, and write down why.
- [ ] **On the Mac, Keynote's trims**: write down the versions of Keynote and PowerPoint (each app's own menu, **About Keynote**, **About Microsoft PowerPoint**). In Keynote, make a placeholder deck of a few slides of made-up words, with a short placeholder video trimmed in Keynote. Drag it in: its video plays whole (Keynote does not tell Drashti a video's trims). Then in Keynote, **File**, **Export To**, **PowerPoint…**, and open that copy in PowerPoint, if it is installed: write down whether its video is trimmed there.
- [ ] **(operators)** **One of the mandir's own decks with animations, on each computer that is a Main** with PowerPoint or Keynote and **Decks With Their Animations on This Computer** ticked: the Mac, where it is on from the start, and the Windows PC only if it was left ticked above (the deck stays on these computers). Drag it in (for one already in the library as pictures, from the parallel-run evenings, it comes in beside that one, asking nothing: delete the pictures one afterwards) and, once the screens and a phone are set up (sections 3 and 5), step through it with **Next** and **Back** beside the deck's own slide show. Every click, transition, video and sound comes as the operators expect; the status along the top says which click is up ("click 1 of 2"); the stage screen shows the click that is up and the next one, and a phone each click's still. Write down how long it took, and anything different.
- [ ] **Import from a Link with a real Dropbox link** (never tried against Dropbox itself: the tests use a stand-in). With a Dropbox link to one of the mandir's own short videos, and one to a mandir folder holding a placeholder `.pptx`, a short MP4, a placeholder PDF and a few pictures, some of them in a folder inside it, each pasted into **File**, **Import from a Link…** with a throwaway playlist open (**+ New**; admin guide, section 14). Write down: whether each link was saved (in **Drashti downloads**) and imported; that the folder's files came into the playlist in its order, its inside folder under a header, its PDF and pictures with them; and each notice's words. If Dropbox refused, write its exact words. Then the same on the other computer, if it is a Main too.
- [ ] **Import from a Link with one of the mandir's own YouTube videos** (never tried against YouTube itself: the tests use a fake yt-dlp). An admin, with a short video from the mandir's own channel and a throwaway playlist open: **File**, **Import from a Link…**, paste its Share link (it takes the best quality up to 1080p); then the same video as its sound, from **Audio**'s **From a Link…** (admin guide, section 14). Once only on each computer that is a Main. Write down how long each took, whether each was saved and imported and plays, and each notice's words (exactly, if it refused). Each time a download is in, its new row is chosen in the playlist, never live: write down whether the operators would mind that in the middle of a sabha.
- [ ] **A 4K video on the Windows PC** (nobody has measured one there): drag in one of the mandir's own 4K video files (since alpha.17 a link takes up to 1080p, so a 4K video comes in as a file). Once the screens are set up (section 3), put it up as a background for a minute on the screens the PC drives: write down whether it plays smoothly on each.
- [ ] **The drop folder**, if the mandir will use one (admin guide, section 18): **File**, **Drop Folder…**, **Choose…** the folder (choosing it turns it on). Put a picture, a short video and a sound in it: a few seconds later each is in **Media** by itself, under **From the drop folder**, and a notice says how many came in. If it is a synced Dropbox or OneDrive folder, try it there: Drashti warns that a folder on this computer alone is safer, and still takes each file only once it has all arrived.
- [ ] **A smart playlist on a USB stick**, if the mandir will use one (admin guide, section 15): **+ New**, **Smart Playlist from a Folder…**, and a folder on the stick holding a few placeholder files. Put one more file in: it joins at the end by itself. Take one out: its item says **Not in the folder**, and still plays. Pull the stick out: the line under the playlist's name says the folder is not there, and nothing is lost; put it back, and it carries on.
- [ ] **(operators)** Open five kirtans they know well and compare with the old program: the words, the line breaks, the Gujarati and Hindi letters, the backgrounds.
- [ ] **Back up**: **File**, **Back Up Library…**, with the media, to the USB drive.
- [ ] **Scheduled backups**: **File**, **Scheduled Backups…**, onto the drive that stays plugged in (admin guide, section 5). Press **Back up now** once and check it finishes.

## 3. Screens and sound (Main, then the node)

- [ ] **Extend, never mirror**: each projector and screen is extended from the computer, never mirrored onto it. On a Mac, **System Settings**, **Displays**, the projector, then **Use as: Extended display**; on Windows, Windows+P, then **Extend**. A mirrored display is one display to Drashti: the line under the top bar then says once how to extend instead.
- [ ] **A display plugged in sets itself**: at Drashti's first start on this computer, and whenever a display it has not used before is plugged in, Drashti uses it at once, asking nothing: the first display that is not the one with the controls (nor the computer's own built-in screen) shows the audience picture, the next one the stage, and any more the audience picture too. A line under the top bar says what it did ("“…” shows the audience picture."), with **Change…**. The screen shows the chosen wallpaper (black until one is chosen, section 4) until something goes up: there is no test slide. **Change…** opens **Screens** at that display, where one click gives it its job: **Audience**, **Stage** or **Not used**, as the screen map in the checklist says. Then unplug it and plug it into another port (or restart the computer): it goes straight back to its job, asking nothing, also a job changed by hand.
- [ ] **Set Up Screens…** (in **View**): **Welcome**, then **Screens**: **Show each display’s number on it**, then for each display its job (one click: **Audience**, **Stage** or **Not used**) and its languages (**A kirtan’s languages on it**), as the screen map in the checklist says, and **Done**. **More setup…** goes on to **Sound** and **Stream**, then **Finish**.
- [ ] **Keep these screens?** now asks only when a change made by hand puts an output on the display the controls are on: in **Set Up Screens…**, **The controls are on this display** marks it; check it is the operator's. Try it once: give that display **Audience**, then **Done**. Drashti asks **Cover the Drashti controls?** first: **Cover the controls**. The output over the controls then asks **Keep these screens?** in its middle for 15 seconds: **Keep** (Enter) or **Go back** (Esc). Try **Go back** once: the screens are as they were, and **Set Up Screens…** shows the choices again to put right. Then once more, and press nothing: after 15 seconds the screens go back by themselves, and a notice says so. Once more, and while it asks, stop Drashti as a power cut would, with a forced quit (on a Mac **Option+Cmd+Esc**, **Drashti**, **Force Quit**; on Windows, in PowerShell, `Stop-Process -Name Drashti -Force`), and start it again: the screens are as they were before that change, and a notice says so. Any other change of the screens asks nothing.
- [ ] **Sound** (**Set Up Screens…**, then **More setup…**): the output to the mixer, and **Play a test tone**. **(operators)** Check the mixer hears it on the right channel.
- [ ] **(operators)** **The mixer's level, once**: this version plays every video and sound at the same loudness (**Even loudness**), in the hall and on the stream, so the hall's level changes from alpha.13: loud music comes down, and quiet talks come up. Drashti measures each file in the background soon after it comes in (the library already there, a minute after this version's first start), and until then plays it as it is. Set the computer's channel on the mixer once, with a typical file playing (one of the mandir's kirtan videos, then a recorded talk), and check the stream's level once (section 7). With an audio playlist playing, put a video with sound up: the music fades down under it (**Music steps aside for a video**, in **Audio**), and comes back up when the video is cleared.
- [ ] Canvas sizes and scaling for any screen that is not 1920 × 1080 (an LED wall).
- [ ] **(operators)** **Each screen group's languages**: in **Screens**, on each group, **A kirtan’s languages on these screens**, as the screen map says (for the stream, **A kirtan’s languages on the stream**, in the **Stream** panel). On the Windows PC, untick two languages quickly, one after the other, then tick both again, also while an import is running: each stays as it was left.
- [ ] **(operators)** **Stage layout**: with the performers, the layout every stage screen shows: **Layout**, in the **Stage screen** panel under the live picture, and **Edit layouts…** beside it for the boxes they want.
- [ ] **(operators)** **The hall's picture on a stage screen**, if the mandir wants it under the stage message, as the old program showed it. The simplest: **Stage** off (in the top bar) makes every stage screen show exactly the audience picture, with the stage message over it. Or, in their stage layout (**Edit layouts…** in the **Stage screen** panel), choose **The audience picture, live** in the list of boxes beside **Add**, then **Add**. It goes under the boxes already there, so the stage message draws over it. Place and size it, and **Save**. On the stage screen it matches the hall's screens: the slide, the background, black-out and the wallpaper. With **Audience** off it keeps the picture and says **Audience off** in its bottom left corner, where a stage message along the top does not cover it (a box of the audience screens' state says "Audience screens off"). On a node with no hall screen of its own that is on, it shows Main's hall. A tablet's stage display (section 5) shows it too, each picture or video in it as a small still (a video input or a window is black there, named in a small line in the box's bottom left corner). With no audience group in **Screens** at all, the box is black and says **No audience screens**, and so does a box of the audience screens' state.
- [ ] **(operators)** **The audience picture box at its smallest**: in the layout editor, drag a corner of **The audience picture, live** in as far as it goes: it stops at 320 × 180, as its **Width** and **Height** say. **Save**, and look at the stage screen from where the performers stand. Turn **Audience** off: **Audience off** can be read in the box; turn it on again.
